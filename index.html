The operating system

The operating system (OS) manages the hardware and lets applications and the user use it. Windows, macOS, Linux, Android and iOS are operating systems.

FunctionWhat the OS does
Managing filesCreates, opens, saves, copies, moves, renames and deletes files and folders.
Handling interruptsDetects interrupts and decides what to do about them (see section 04).
Providing an interfaceGives the user a way to interact with the computer, such as a GUI (windows, icons, menus) or a command line.
Managing peripherals and driversUses device drivers so it can talk to devices such as printers and keyboards.
Managing memoryDecides which programs and data are in RAM, and stops programs using each other's memory.
Managing multitaskingLets several programs run at once by sharing the processor's time between them.
Providing a platform for running applicationsGives applications a way to use the hardware without controlling it directly.
Providing system securityUses passwords, firewalls and updates to protect the system from attacks.
Managing user accountsLets each user have their own login, files and settings, with access only to their own data.

Hardware, firmware and the operating system

Software runs in layers. Each layer runs on the one below it.

  • Firmware is software stored permanently in ROM (non-volatile memory). It controls the hardware at the lowest level.
  • The bootloader is firmware. When the computer is switched on, it loads the operating system from storage into RAM.
  • The operating system then manages the hardware and provides a platform for applications to run on.
The bootloader must be in ROM, because RAM is empty when the power is off. ROM keeps its contents without power.

Interrupts

An interrupt is a signal sent to the processor to say that something needs its attention.

Hardware interruptscome from a device:
  • a key is pressed
  • the mouse is moved
  • the printer runs out of paper
Software interruptscome from a program:
  • a program tries to divide by zero
  • two programs try to use the same memory
  • a program asks the OS to do something

How an interrupt is handled

  1. The processor is running a program.
  2. A device or program sends an interrupt to the processor.
  3. The processor checks for interrupts after each instruction. It checks the interrupt's priority. If it is more important than the current task, the processor saves the current task.
  4. The processor runs the interrupt service routine (ISR): the code that deals with that interrupt.
  5. When the ISR is finished, the saved task is restored.
  6. The processor carries on with the program from where it stopped.
Example: you press Ctrl+C while a file is copying. The keyboard sends an interrupt. The ISR cancels the copy, and the processor goes back to what it was doing.

High-level and low-level languages

High-level language

Advantages

  • easier to read, write and debug, because it is close to English
  • portable: works on different types of computer
  • one line can do the work of many machine code instructions

Disadvantages

  • must be translated before it runs
  • no direct control of the hardware
  • the program may be larger and slower
Low-level language

Advantages

  • direct control of the hardware, such as registers and memory
  • programs can be faster and use less memory
  • good for device drivers and embedded systems

Disadvantages

  • hard to read, write and debug
  • machine dependent: only works on one type of processor
  • needs a good knowledge of the hardware

Assembly language and assemblers

Assembly language is a low-level language that uses short codes called mnemonics instead of binary.

The binary codes are examples. Real codes depend on the processor.
  • Each assembly instruction matches one machine code instruction.
  • The processor cannot run assembly language directly, so it must be translated by an assembler.
  • Programmers use assembly language when they need direct control of the hardware, or a program that is very fast or uses very little memory.

Compilers and interpreters

Both translate a high-level language into machine code. They do it in different ways.

CompilerInterpreter
How it translatesThe whole program at onceOne line at a time, running each line straight away
What it producesAn executable file that can run without the compilerNo executable file; the interpreter is needed every time
ErrorsA list of all errors at the end; the program will not run until they are fixedStops at the first error; you fix it and carry on
Best forFinished programs that are given to usersWriting and testing (debugging) a program
AdvantagesRuns fast once compiled. Users cannot see the source code.Easy to debug: you see exactly where the error is. Can test part of a program.
DisadvantagesHarder to debug. Must recompile after every change.Slower to run. The source code must be given to users.

Integrated development environment (IDE)

An IDE is software that gives a programmer all the tools to write, translate and test code in one place. IDLE, Thonny and Visual Studio Code are examples.

IDE functionWhat it does
Code editorWhere the programmer types and edits the code.
Run-time environmentLets the program run and be tested inside the IDE.
TranslatorA built-in compiler or interpreter that turns the code into machine code.
Error diagnosticsFinds errors and shows where they are, with a message about what is wrong.
Auto-completionSuggests the rest of a keyword or variable name as you type.
Auto-correctionFixes common typing mistakes automatically.
PrettyprintShows keywords in colour and indents the code, so it is easier to read.
